1. How does a CPU work?
A CPU reads instructions from memory and executes it. It is dumb, so it needs to
be told every little thing in a logical manner.

Ex: (machine code) $C622 has two bytes:
- first byte $C6 means "add to register A"
- second byte 22 means "add 22 (value)"
so the instruction means "add 22 to register A"

These instructions are in binary/hexadecimal, they go through an assembler that
turns them from `ADD R6, 22` to `$C622`

---

2. What is an emulator?
An emulator takes the machine code of the program in the target machine, interprets
it, and replicates its functionality in the host machine.

Ex: $C622 in target machine (original GameBoy) translated to assembly:
register[5] += 0x22;

When emulating advanced machines, you also have to emulate the GPU, sound chip, etc.
but at its core, its just this.

3. CHIP-8 description
The components to emulate are:

1. 16 8-bit registers
CPUs have registers they use while executing instructions. They load an instruction
from memory to the register, execute them, then load the result back into memory.

CHIP-8 has 16 8-bit registers labeled V0 to VF. Each can hold 0x00 to 0xFF.
VF is used as a flag to hold information about the result of the operation.

Note: each register is 1 byte in terms of memory. So 16 bytes of registers in total.

2. 4K bytes memory
Because the CPU has such little memory to work with, it has a large chunk if general
memory outside.

CHIP-8 has 4096 bytes of memory, ranging from 0x000 to 0xFFF. They are partitioned as
follows.

- 0x000 to 0x1FF: reserved for the interpreter (we will not touch this portion).
- 0x200 to 0xFFF: space for the program instructions + free space left.
- 0x050 to 0x0A0: for characters 0 through F because ROMs will be looking for these.

these are, 512 bytes, 3584 bytes, and 81 bytes (inside the 512 bytes) respectively.

3. 16-bit index register
This stores the memory address (it is 2 bytes because we need all 4096 bytes to be
addressable, which requires at least 12 bits).

Note: I don't understand why we need index registers if memory is random-access.

4. 16-bit program counter
This is a special register that holds the next instruction to execute. Since
instructions are stored in memory, the CPU needs to fetch instructions. This register
holds the address of the next instruction to execute.

Since a single instruction is 2 bytes, the CPU needs to fetch the address at PC and
the address at PC+1 to execute the instruction. Then, the PC is incremented by 2.
Then, the instruction is executed.

Note that the PC is updated before the instruction is executed because some
instructions change the value of the PC.

5. 16-level stack
When a program calls a function, the PC jumps to that part of the program in memory.
When the function returns, the PC needs to continue where it left off. So, the value
of the PC is stored in the stack so that it can be restored once the function
returns.

The `CALL` instruction jumps to a different part of the program. This also pushes
the current value of the PC to the stack.
The `RET` instruction pops the top of the stack and the PC is set to this value.

Multiple levels allow multiple level of function calls inside function calls.
CHIP-8 can hold 16 PCs at once.

6. 8-bit stack pointer
Because we can store multiple PCs in a 16 level stack, we need a pointer to know
which PC we are currently at. The stack pointer SP tracks this. It tracks the 
next location where the PC will be stored.

[0 0 0 0 0] (5 level stack, SP = 0 initially)
$200: CALL $204
$202: EXIT
$204: ADD V1, 22
$206: RET

PC: $202, current instruction: CALL $204
SP: 1, [$202 0 0 0 0]

You figure out the rest.

7. 8-bit Delay Timer
A timer that ticks down to 0 every 1/60-th of a second. A 60Hz timer that ticks
down by 1 if it is non-zero.

8. 8-bit Sound Timer
Same as the 8-bit Delay Timer but also emits a sound if it is non-zero.

10. 64x32 Monochrome Display Memory
CHIP-8 has a dedicated 64x32 buffer for storing sprites. 64 pixels wide, 32
pixels high.

Each pixel can be either on or off. The buffer is a `uint32` so when the
pixel is on: 0xFFFFFFFF and off: 0x00000000

The DRAW instruction iterates over each pixel of the sprite and XORs it with
the display pixel.

To move a 1x1 sprite from position {200, 200} in the display screen, we first
call DRAW at {200, 200} to erase the pixel, then call DRAW at {201, 201} to 
move it forward. CHIP-8 graphics is flickery for this reason.
